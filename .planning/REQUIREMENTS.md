# Requirements: TinyToolCaller — Production Deployment Infrastructure

**Defined:** 2026-08-21
**Core Value:** Deploy TinyToolCaller behind a production-grade REST API with deterministic safety controls

## v1 Requirements

### API Server

- [ ] **API-01**: FastAPI server starts and serves the `/tool-call` endpoint on a configurable port
- [ ] **API-02**: `/tool-call` accepts POST with JSON body `{"request": "...", "tools": [...]}`
- [ ] **API-03**: `/tool-call` returns `{"name": "...", "arguments": {...}}` on success
- [ ] **API-04**: `/tool-call` returns `{"error": "unparseable"}` when JSON cannot be extracted
- [ ] **API-05**: Server exposes `/health` and `/ready` endpoints for Kubernetes probes
- [ ] **API-06**: Server loads model at startup (no per-request loading latency)
- [ ] **API-07**: CLI mode: `python -m tinytoolcaller.serve --model <path> --prompt "..." --tools [...]` for one-shot inference

### Validation Stack (§22.1 implementation)

- [ ] **VAL-01**: Extract JSON from raw model output using `formatting.extract_json`
- [ ] **VAL-02**: Tool allowlist check before execution (application-level, not model-level)
- [ ] **VAL-03**: JSON Schema validation on predicted arguments using `jsonschema`
- [ ] **VAL-04**: Authorization hook — injectable callable for per-user, per-tool, per-argument scoping
- [ ] **VAL-05**: Retry-with-repair integration — one retry when JSON is invalid
- [ ] **VAL-06**: Audit logging of every request with the §23 log schema

### Docker Packaging

- [ ] **DOCK-01**: Dockerfile with multi-stage build (base Python → install deps → copy model → serve)
- [ ] **DOCK-02**: GPU variant with CUDA + bitsandbytes support
- [ ] **DOCK-03**: CPU-only variant for development/testing
- [ ] **DOCK-04**#### docker-compose.yml** for local deployment with one command
- [ ] **DOCK-05**: `.dockerignore` excludes unnecessary files (tests, scripts, .git)

### CI/CD Pipeline

- [ ] **CICD-01**: GitHub Actions workflow runs on PRs to main: lint + test + build Docker
- [ ] **CICD-02**: On merge to main: build and push Docker image to GitHub Container Registry
- [ ] **CICD-03**: Automated tagging with git SHA and semantic version

### Documentation

- [ ] **DOC-01**: README section: "Quick Start — Run the Server" with docker-compose command
- [ ] **DOC-02**: README section: "Configuration" — all environment variables documented
- [ ] **DOC-03**: README section: "Production Deployment" — Kubernetes, monitoring, alerting
- [ ] **DOC-04**: OpenAPI docs auto-generated by FastAPI at `/docs`

### Codebase Cleanup

- [ ] **CLN-01**: Remove orphaned `TinyToolCaller-files/` directory from repo
- [ ] **CLN-02**: Pin dependency versions in `requirements.txt` with tested minimums
- [ ] **CLN-03**: Add `update/architecture.py` diagram reflecting deployment architecture

## v2 Requirements

- **V2-01**: vLLM/TGI integration for production-grade batching
- **V2-02**: LoRA adapter hot-swap per request (multi-tenant without redeploy)
- **V2-03**: Prometheus metrics endpoint for monitoring
- **V2-04**: Horizontal Pod Autoscaler configuration for Kubernetes
- **V2-05**: Model warm-up on startup to avoid cold-start latency

## Out of Scope

| Feature | Reason |
|---------|--------|
| Multi-turn tool orchestration | Out of scope per publication §4 |
| User authentication (API keys, OAuth) | Specific to deployment environment; auth hook is provided |
| Model monitoring dashboard | Log schema provided; dashboard is deployment-specific |
| Load testing suite | Would depend on specific hardware; guidance provided in docs |
