## API Contract

### 1. Endpoint: `POST /tool-call`

**Purpose:** Accept a natural-language request + available tool schemas, return the predicted tool call.

**Request Schema (`POST /tool-call`)**

| Field | Type | Required | Description | Constraints |
|-------|------|----------|-------------|-------------|
| `request` | `string` | Yes | Natural-language user request | 1-4096 characters |
| `tools` | `array[object]` | Yes | Available tool definitions (JSON Schema format) | 1-100 items; each item MUST have `name` (string) and `parameters` (JSON Schema object) |

**Example request:**
```json
{
  "request": "What's the weather in Tokyo?",
  "tools": [
    {
      "name": "get_weather",
      "description": "Get current weather for a city",
      "parameters": {
        "type": "object",
        "properties": {
          "city": {"type": "string"},
          "units": {"type": "string", "enum": ["celsius", "fahrenheit"]}
        },
        "required": ["city"]
      }
    }
  ]
}
```

**Success Response (200 OK)**

| Field | Type | Description |
|-------|------|-------------|
| `name` | `string` | The predicted tool name |
| `arguments` | `object` | The predicted tool arguments (as JSON object) |

**Example success response:**
```json
{
  "name": "get_weather",
  "arguments": {
    "city": "Tokyo",
    "units": "celsius"
  }
}
```

**Error Responses**

| Status Code | Error Condition | Response Body | Validation Layer |
|-------------|----------------|---------------|------------------|
| **400 Bad Request** | Invalid request body (Pydantic validation failure) | `{"detail": [{"loc": ["body", "tools"], "msg": "field required", "type": "value_error.missing"}]}` | FastAPI/Pydantic (layer 0) |
| **422 Unprocessable Entity** | JSON malformed, empty request, request too long | `{"detail": {"error": "unparseable", "message": "Could not extract JSON from model output"}}` | Layer 1: extract_json |
| **422 Unprocessable Entity** | Tool name not in allowlist | `{"detail": {"error": "tool_not_allowed", "message": "Tool 'get_stock_price' is not in the allowed tools list"}}` | Layer 2: allowlist |
| **422 Unprocessable Entity** | Arguments fail JSON Schema validation | `{"detail": {"error": "invalid_arguments", "message": "Argument validation failed", "details": [{"field": "city", "error": "'city' is a required property"}]}}` | Layer 3: schema |
| **500 Internal Server Error** | Model inference failure, GPU OOM, crash | `{"detail": {"error": "internal_error", "message": "Model inference failed"}}` | Catch-all |
| **503 Service Unavailable** | Model not loaded (startup race or reload) | `{"detail": {"error": "model_not_ready", "message": "Model is still loading"}}` | Startup gate |

## CLI Contract

**Entry point:** `python -m tinytoolcaller.serve`

**Mode switching:**
- When `--prompt` is provided → CLI mode (one-shot, no server)
- When `--prompt` is NOT provided → server mode (starts uvicorn, serves API)

### Server Mode

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `--model` | `str` | (required) | Path to model directory or HuggingFace Hub ID |
| `--port` | `int` | `8000` | Server port |
| `--host` | `str` | `0.0.0.0` | Server bind address |
| `--allowlist` | `str` | `None` | Path to JSON file with allowed tool names (optional; no allowlist filtering if omitted) |

**Behaviour:**
1. Load model at startup (blocks until ready)
2. Serve `POST /tool-call` on the configured port
3. Log each request to stdout with timestamp and status

### CLI Mode

| Argument | Type | Required | Description |
|----------|------|----------|-------------|
| `--model` | `str` | Yes | Path to model directory or HuggingFace Hub ID |
| `--prompt` | `str` | Yes | Natural-language user request (inline string) |
| `--tools` | `json` | Yes | Tool definitions as inline JSON string |
| `--allowlist` | `str` | No | Path to JSON file with allowed tool names |

**Behaviour:**
1. Load model (cold start — startup overhead per invocation)
2. Run inference through full validation stack
3. Print result to stdout as JSON
4. Exit with code 0 on success, code 1 on error

**CLI output format (stdout):**
```json
// On success — one JSON line
{"name": "get_weather", "arguments": {"city": "Tokyo"}}

// On validation failure — one JSON line
{"error": "unparseable", "message": "Could not extract JSON from model output"}
```

**Exit codes:**
| Code | Meaning |
|------|---------|
| 0 | Success (tool call produced and validated) |
| 1 | Error (validation failure or inference crash) |

## Validation Stack Contract (6-Layer, Phase 1: Layers 1-5)

Reference: Publication §22.1, STATE.md Decisions table.

| Layer | Name | Responsibility | Input | Output on Failure |
|-------|------|----------------|-------|-------------------|
| 0 | **Pydantic** (FastAPI) | Validate incoming HTTP request body structure | Raw JSON body | 400 — Pydantic `ValidationError` detail |
| 1 | **extract_json** | Parse raw model output into JSON dict | Raw model output string | 422 — `{"error": "unparseable"}` |
| 2 | **Allowlist** | Check `name` is in configured allowed tools list | `name` field from extracted JSON | 422 — `{"error": "tool_not_allowed", "message": "..."}` |
| 3 | **JSON Schema** | Validate `arguments` against the tool's `parameters` schema | `arguments` object + tool's JSON Schema | 422 — `{"error": "invalid_arguments", "details": [...]}` |
| 4 | **Authorization** (deferred to Phase 2) | Injectable callable for per-user/per-tool scoping | Auth context | Deferred — no-op pass-through in Phase 1 |
| 5 | **Retry-with-Repair** | One retry if layer 1 fails (re-prompt model with its faulty output) | Raw model output | After 1 retry still fails → pass through layer 1 error |
| 6 | **Audit Logging** (deferred to Phase 2) | Log request with §23 schema | Request + result | Deferred — stdout logging only in Phase 1 |

**Validation flow:**
```text
Client → [Layer 0: Pydantic] → Model (generate) → [Layer 1: extract_json]
  → [Layer 5: retry if layer 1 failed, max 1 attempt] → [Layer 2: allowlist]
  → [Layer 3: jsonschema] → [Layer 4: auth (no-op in P1)] → Response
```

**Retry-with-Repair contract (Layer 5):**
- Only activates when `extract_json` returns `None` at layer 1
- Re-prompts the model using `repair.repair()` with `REPAIR_INSTRUCTION` + faulty output
- Default: 1 retry (matches `repair.py:max_attempts=1`)
- On retry success → proceeds to layers 2-3 normally
- On retry failure → returns layer 1 error as if no retry happened

## Copywriting Contract

### API Error Messages

| Condition | HTTP Code | Error Code | Message Template |
|-----------|-----------|------------|------------------|
| Invalid request body | 400 | _(Pydantic default)_ | FastAPI-generated `{"detail": [...]}` with field-level errors |
| JSON not extractable | 422 | `unparseable` | `"Could not extract JSON from model output"` |
| Tool not in allowlist | 422 | `tool_not_allowed` | `"Tool '{name}' is not in the allowed tools list"` |
| Arguments invalid | 422 | `invalid_arguments` | `"Argument validation failed"` + `details` array |
| Model not loaded | 503 | `model_not_ready` | `"Model is still loading"` |
| Inference crash | 500 | `internal_error` | `"Model inference failed"` |

### CLI Output Messages

| Condition | stdout | stderr | Exit Code |
|-----------|--------|--------|-----------|
| Success | `{"name": "...", "arguments": {...}}` | _(empty)_ | 0 |
| Validation failure | `{"error": "...", "message": "..."}` | _(empty)_ | 1 |
| Inference crash | `{"error": "internal_error", "message": "..."}` | Crash traceback | 1 |
| Missing required arg | _(empty)_ | `"Error: --model is required"` + usage | 2 |

### Server Startup Messages

| Condition | Print to stdout |
|-----------|-----------------|
| Model loading | `"[1] Loading model from {path} ..."` |
| Model loaded | `"[1] Model loaded in {:.2f}s"` |
| Server starting | `"[2] Starting server on http://{host}:{port}"` |
| Server started | `"[2] Server started — docs at http://{host}:{port}/docs"` |
| Allowlist loaded (if provided) | `"[1] Allowlist loaded — {N} tools allowed"` |
| No allowlist | `"[1] No allowlist — all tools accepted"` |
| Model loading failed | `"[1] ERROR: Failed to load model — {error_message}"` → exit 1 |

### Server Request Log Format (Phase 1 — simple, non-structured)

```
{timestamp} POST /tool-call 200 {latency_ms}ms tool={name}
{timestamp} POST /tool-call 422 {latency_ms}ms error=unparseable
{timestamp} POST /tool-call 500 {latency_ms}ms error=internal_error
```

Format: space-delimited key=value pairs on a single line per request.

**Not in Phase 1** (deferred to Phase 2):
- Structured JSON logging with §23 schema
- `request_id` propagation
- `auth_context` in logs

## OpenAPI / Docs Contract

**What FastAPI auto-generates (Phase 1 defaults):**

| Property | Setting |
|----------|---------|
| Server title | `TinyToolCaller` |
| Server version | `0.1.0` (from `__init__.py`) |
| Docs URL | `/docs` |
| Redoc URL | `/redoc` |
| OpenAPI JSON | `/openapi.json` |
| Schema naming | Pydantic model names (PascalCase) |
| Example values | Pydantic model field examples (none in Phase 1) |

**Explicit contract for Phase 1:**
- `POST /tool-call` request body MUST be a well-typed Pydantic model with:
  - `request: str` with `min_length=1, max_length=4096`
  - `tools: list[ToolDefinition]` where `ToolDefinition` has `name: str` + `parameters: dict`
- Success response MUST be a Pydantic model with `name: str` + `arguments: dict`
- Error responses MUST be documented via `response_model` or `responses` decorator with `description`
- 422 responses SHOULD include the `ValidationError` schema (FastAPI default)
